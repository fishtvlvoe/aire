## Requirements

### Requirement: Local Web SHALL use same-origin discovery proxy

Development local Web SHALL perform `Z10Web`-first discovery through a same-origin localhost proxy. The browser SHALL NOT call `Z10Web`, EasyMap R02, COP, NLSC, public cadastral, or convenience-service endpoints directly. When `Z10Web` returns multiple building candidates for the same doorplate and the input address includes floor-or-unit detail, the proxy SHALL use `R02` or equivalent zero-cost building detail as a cross-check to reduce the candidates to a unique building number when possible.

Browser-local-first production SHALL perform the same zero-cost discovery through `POST /api/address-discovery` on the Taiwan land proxy origin. The production browser SHALL NOT call `POST /api/local/address-discovery` on the Cloudflare Pages origin and SHALL NOT call EasyMap endpoints directly.

#### Scenario: Multi-candidate Z10Web result is narrowed by R02 floor-unit evidence

- **GIVEN** a doorplate address query returns multiple building candidates from `Z10Web`
- **AND** the input address contains floor-or-unit detail such as `8樓之1`
- **WHEN** the local discovery proxy completes the zero-cost cross-check
- **THEN** the proxy SHALL return a single confirmed building candidate when exactly one candidate matches the normalized floor-or-unit detail
- **AND** the response SHALL keep `totalCostCents = 0`
- **AND** the browser SHALL not need to render a candidate-selection step for that case.

#### Scenario: Cross-check cannot produce a unique building number

- **GIVEN** a doorplate address query returns multiple building candidates from `Z10Web`
- **WHEN** the proxy cannot derive a unique match from `R02` or building-detail floor labels
- **THEN** the proxy SHALL preserve the multi-candidate response
- **AND** SHALL require manual candidate selection instead of guessing.

#### Scenario: Browser production calls Taiwan address discovery proxy

- **GIVEN** browser-local-first mode is enabled in production
- **WHEN** the user searches a full Taiwan address
- **THEN** the browser SHALL send POST /api/address-discovery to the configured Taiwan land proxy origin
- **AND** the response SHALL use the same normalized discovery contract as local Web
- **AND** totalCostCents SHALL be 0.

#### Scenario: Taiwan proxy is stateless for discovery

- **WHEN** POST /api/address-discovery receives an address request
- **THEN** the proxy SHALL forward or execute discovery and return the normalized result
- **AND** the proxy SHALL NOT write the address, candidates, owner data, PDF data, or registry payload into cloud storage.

##### Example: Stateless proxy request

- **GIVEN** request body `{ "address": "台南市永康區勝利街58巷4號", "allowMockFallback": false }`
- **WHEN** POST /api/address-discovery completes
- **THEN** the response includes `normalizedAddress = "台南市永康區勝利街58巷4號"`
- **AND** no Cloudflare KV, D1, R2, or Cloud Run file write is performed for that address.

### Requirement: Discovery contract SHALL expose input kind and selection gate

Local Web proxy and Desktop discovery responses SHALL include the classified input kind, intended object type, parsed fields, candidate confidence, whether candidate selection is required, suggested corrections when available, and a zero-cost marker. The contract SHALL allow the UI and backend to distinguish confirmed registry keys from discovery-only candidates.

#### Scenario: Doorplate and land descriptor share one contract

- **GIVEN** one user enters a doorplate address
- **AND** another user enters a section and land number
- **WHEN** local Web or Desktop discovery completes
- **THEN** both responses SHALL use the same `DiscoveryResult` shape
- **AND** each response SHALL identify `inputKind`
- **AND** each response SHALL identify intended object type as building, land, or unknown
- **AND** each response SHALL set `totalCostCents = 0`.

#### Scenario: Discovery needs user selection

- **GIVEN** discovery returns more than one possible registry target
- **WHEN** the proxy returns the discovery result
- **THEN** the result SHALL set `requiresCandidateSelection = true`
- **AND** it SHALL NOT contain `confirmed_registry_match`.

### Requirement: Web and Desktop SHALL share a unified discovery contract
