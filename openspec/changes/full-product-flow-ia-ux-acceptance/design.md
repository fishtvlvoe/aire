## Context

使用者目前看到的問題不是單一 CSS 錯誤，而是資訊架構沒有遵守「一個功能只在一個主要位置出現」：

```
左側一級選單
  ↓
二級功能頁
  ↓
頁內只放該功能需要的工作內容
```

錯誤狀態包含：

- `地政資料 > 地政查詢` 與 `案件管理 > 新增案件` 重複，實際上都是起案流程。
- 設定頁內又放一個 `設定分類`，與左側主選單重複。
- `功能開關` 因 section 未被識別，出現兩組 `授權與升級` toggle。
- Dev/SuperAdmin 類開發工具出現在客戶設定流程中。
- 工作台的 `重新查詢`、`產生補件清單`、分頁按鈕看起來可操作，但後端閉環尚未完成。
- 本機 fallback 對地址判斷過度粗糙，可能把建物地址標成農地或農舍。

## Goals

- Fish 回來後可以用本機 `localhost:3000` 從新增物件走到產出文件與設定頁驗收。
- 左側選單作為唯一全域導覽來源；頁內不再重複做另一套分類。
- 每個功能頁只顯示自己的內容：案件、工作台、補件、資料來源、費用、PDF、匯出、授權、功能開關、升級。
- 對客戶無用或尚未可用的功能要移除、隱藏，或改成明確不可用狀態，不得像已完成按鈕。
- 地址地政判斷測試要覆蓋「一般建物地址」與「農地/土地地址」。

## Non-Goals

- 不把所有未完成 API 功能一次補完。
- 不做付費結帳與正式升級收款。
- 不把開發者 Super Admin 當作客戶功能保留在設定頁。
- 不把頁面做成展示 demo；必須是可驗收的產品流程。

## IA Contract

### 左側選單

| 一級 | 二級 | 說明 |
| --- | --- | --- |
| 案件管理 | 案件總覽、新增案件、說明書工作台、補件清單 | 新增物件只在案件管理底下 |
| 地政資料 | 資料來源、費用紀錄 | 只看地政資料邊界與帳務，不起案 |
| 產出文件 | PDF 預覽、列印與匯出 | 只處理輸出 |
| 系統設定 | 地政授權、功能開關、授權與升級 | 只處理設定與授權 |

### 頁內內容

- 頁內不得再顯示與左側相同的功能分類清單。
- 頁內按鈕必須是該頁主要任務的直接動作。
- 不可操作或未接後端的功能不能以 primary button 呈現。

## Flow Contract

```
新增案件
  → 輸入地址
  → 判斷地政資料
  → 顯示建物/土地/需人工確認
  → 建立案件
  → 案件工作台
  → 欄位審核 / 補件 / 費用摘要
  → PDF 預覽或列印匯出
  → 系統設定只處理授權、開關與升級
```

若地政 API 尚未可用，fallback 只能標為「建物」、「土地」或「需要人工確認」，不得推測成農地或農舍。

## Acceptance Plan

- 單元測試：設定頁 section 去重、功能開關只渲染一次、地址判斷不誤判。
- E2E：逐一點擊左側二級選單，驗證每個頁面 heading、主要內容、不可混入內容與 URL。
- E2E：新增案件流程必須先判斷地政資料；一般建物地址顯示建物，不顯示農地或農舍。
- E2E：工作台不顯示看似可執行但沒有閉環的假按鈕。
- Spectra gate：`spectra analyze full-product-flow-ia-ux-acceptance --json` 與 `spectra validate full-product-flow-ia-ux-acceptance` 必須無 Critical / Warning。
