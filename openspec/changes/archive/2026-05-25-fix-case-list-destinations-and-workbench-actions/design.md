## Context

使用者的心理模型是：

```text
左側二級選單
  → 只進入該功能的清單或處理情境
  → 點案件後要延續這個情境
  → 案件內按鈕如果能點，就必須有結果
```

目前 UI 違反這個模型：多個二級清單點案件後都回到同一個工作台，而且工作台內的分頁/動作像按鈕但沒有狀態。

## UX Contract

### 案件列目的地

| 目前頁面 | 點案件列後 |
| --- | --- |
| 案件總覽 | `/cases/:id` |
| 說明書工作台 | `/cases/:id` |
| 補件清單 | `/cases/:id?tab=supplements` |
| PDF 預覽 | `/cases/:id/preview` |
| 列印與匯出 | `/cases/:id/preview?mode=export` |

### 工作台 tabs

工作台只保留一個案件內工作區，右側 tabs 代表三級任務：

- 欄位：欄位審核、帶入狀態與補件狀態。
- 資料來源：每個欄位的來源服務與可/不可自動取得邊界。
- 補件：可加入補件清單、現場必問與手動覆蓋狀態。
- 費用：本案件地政 API 成功/失敗紀錄摘要。
- PDF 檢查：PDF 預覽入口與尚未完成欄位提示。

### 假按鈕處理

- 未串後端的地政重查與補件產生，不顯示為主要按鈕，只顯示為「後端串接中」狀態。
- 本機可處理的動作可以保留為按鈕，但點擊後要更新畫面文字。
- `預覽 PDF` 是已存在路由，應該是連結到 `/cases/:id/preview`。

### 費用紀錄

`費用紀錄` 是地政 API 帳務頁，不是 AIRE 方案功能頁。它 SHALL：

- 顯示地政 API 明細列：時間、服務、地號/建號或案件、成功/失敗、交易序號、費用。
- 顯示成功費用加總。
- 失敗列顯示 `0 元`。
- 明確標示 Google、空拍、AI 格局圖等 AIRE 方案費用不列入地政 API 帳務。

### PDF 圖資補件入口

`資料來源` 頁的 PDF 圖資欄位 SHALL 提供基本款也能使用的手動上傳入口：

| 圖資 | 基本款 | 進階/高級 |
| --- | --- | --- |
| 地籍圖 | 手動上傳 | 可由地政/圖資整理帶入 |
| 空拍圖 | 手動上傳 | 可自動取得後帶入 |
| 格局圖 | 手動上傳 | 可用 AI 整理 |
| 地標圖 | 手動上傳 | 可由地圖資料產生 |

本 SR 先補 UI 與本機狀態，正式檔案持久化由既有 `case_assets` 路徑承接。

## Acceptance

- 單元測試確認不同 `view` 的案件列 destination 不同。
- 單元測試確認工作台 tabs 切換內容、補件按鈕有 visible feedback。
- 單元測試確認費用頁顯示明細與總計，沒有把 AIRE 方案費混入地政 API 明細。
- 單元測試確認資料來源頁有四個 PDF 圖資上傳入口。
- E2E 點過 `補件清單`、`PDF 預覽`、`列印與匯出` 的案件列並驗證 URL/heading。
