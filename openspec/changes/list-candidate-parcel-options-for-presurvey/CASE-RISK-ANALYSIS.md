# 同類案件風險分析

## 分析結論

裕農路不是單一地址錯誤，而是目前資料流把「候選資料」與「正式可進 PDF 的資料」切得太硬。只要案件停在候選資料、地址反查失敗、建號未確認或圖片座標沒有被帶入，就會產生同樣的空白物調表。

目前風險最高的是大樓、華廈、公寓這類有「樓」「之」「巷弄門牌 + 戶別」的案件。土地案與已經有正式 trusted registry payload 的案件風險較低。

## 會出問題的案件類型

| 案件類型 | 典型地址/資料狀態 | 風險 | 會空白的內容 |
| --- | --- | --- | --- |

| 只有 `0001` / `0001-0001` placeholder | mock 或地址 lookup fallback 產生的地號 | 高 | 系統拒絕用 placeholder 做正式 pull，欄位留空 |

## 程式層根因

1. 新增案件只保存第一筆候選

新增案件頁建立 case 時會把地址 lookup 結果寫入 `land_registry_data`，但目前只取 `parcels[0]`。多筆候選不會完整保存，所以工作台與 PDF 沒有全部候選可比。

2. 候選資料被標成不能進正式 PDF

`createRegistryProvenancePayload()` 會把 `public_candidate` 標成 `candidate` 且 `trustedForPdf:false`。這個標記本身是合理的，但目前 PDF 沒有另一條「前期物調可用候選資料」的渲染路徑。

3. PDF assembly 只接受正式 trusted 資料

PDF 組裝時，只有 `moi_api/manual + success/manual_confirmed + trustedForPdf:true` 會進入正式欄位。候選資料存在也會被濾掉，因此欄位空白。

4. placeholder 地號會阻止正式 pull

`0001`、`00001`、含「候選/待確認/待補」會被視為 placeholder，不會拿去正式 pull。這避免亂扣款，但也讓只有 placeholder 的案件完全沒有補救路徑。

5. mock pull 也會被濾掉

dev/mock backend 的地政 pull 回傳 `source:"mock"`，PDF assembly 會把 mock 資料清掉，避免假資料進正式輸出。這對正式性是對的，但對 demo/dev 驗收會造成「看起來查了，PDF 還是空」。

6. 圖片需要座標，不能只靠完整地址

位置圖、生活機能、航拍圖、街景都依賴 `geoLat/geoLng`。若正式地政資料沒有座標，會改用地址 geocode；裕農路完整地址 geocode 失敗時，如果候選座標沒有被讀取，就沒有圖片。

7. 不同瀏覽器資料不同是 localStorage 隔離

目前 dev/mock 模式的 cases 存在每個瀏覽器自己的 `aire-mock-store`。Chrome 新增的案件不會自動同步到另一個瀏覽器或另一個 profile，所以看到案件數、補件狀態、PDF 資料不同是預期的 mock 限制，不是同一份後端資料。

## 驗證到的 PDF 現象

### 裕農路 PDF

- `pdftotext` 顯示裕農路 PDF 有地址與樓層 `8樓之1`，但登記坪數、主建坪、用途、完成日、屋齡等欄位空白。
- `pdfimages -list` 顯示沒有圖片物件，所以位置圖、航拍圖、建物外觀都沒有真正嵌入。
- PDF 有實價登錄行情，表示不是整份組裝壞掉，而是地政/圖資資料鏈沒有進入 PDF。

### 勝利街 `0005-說明書.pdf`

- `pdftotext` 顯示地號只有 `0001`，建物面積、用途、完成日、屋齡空白。
- 所有權人有顯示，代表 owner row 本身有保存，但建物登記資料沒有進來。
- `pdfimages -list` 同樣沒有圖片物件。

### 舊和平東路 PDF

- `pdfimages -list` 有 3 張圖片物件，代表舊輸出或 seed path 曾能嵌入圖資。
- 這證明圖片系統不是完全不能產圖，而是新案件在座標取得與 fallback 上斷掉。

## 需要修的方向

這不是「要不要正式查謄本」的問題，而是要新增「前期物調候選模式」：

```text
地址輸入
  ↓
正式門牌建號查詢成功
  → trusted 資料進 PDF

正式門牌建號查詢失敗 / 多筆 / API 權限不足
  ↓
列出所有土地/建物候選
  ↓
可暫用一筆候選，或用同棟同尾碼戶別推測
  ↓
PDF 顯示候選/推測資料 + 明確警示
  ↓
屋主確認後再升級為正式建號/地號
```

PDF 固定警示文字：

> 地政資料，最終以正式謄本為主；本說明書不代表完整資訊。

## 工程判斷

短期不要再讓候選資料卡在 JSON 預覽裡。候選資料不是正式謄本，但它是前期業務洽談需要的參考資料。正確做法是把資料分層：

- 正式資料：可用於正式欄位。
- 候選資料：可用於前期物調，必須標示待確認。
- 推測資料：只能作為參考，必須標示非登記資料。

這樣可以同時避免空白 PDF，也避免把未確認資料誤認為正式謄本。
