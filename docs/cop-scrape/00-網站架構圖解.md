## 二、API 端點對照表

| 頁面 | API 端點 | 方法 | 說明 | 筆數 |
|------|---------|------|------|------|
| 入口首頁 | `/api/Portal` | GET | 新聞 + 熱門服務 + 熱門應用 | 1 筆 |
| 服務列表 | `/api/Services/service_list` | POST | 服務基本資訊（含描述） | **僅前 10 筆** |
| 服務價格 | `/api/ServicesInfo/pricing` | GET | 全部服務價格 + 文件連結 | **63 筆** |
| 使用統計 | `/api/ServicesInfo/serviceUsage` | GET | 服務調用次數統計 | 22 筆（分 3 頁） |
| 最新消息 | `/api/SiteInfo/news` | GET | 平台公告新聞 | 多筆 |
| 常見問題 | `/api/SiteInfo/qa` | GET | FAQ 問答內容 | 多筆 |

## 三、重要發現

### 1. 服務總數 = 63 個
- API 服務（MOI_API_xxx）：約 45 個
- WFS 服務（MOI_WFS_xxx）：6 個
- WMS 服務（MOI_WMS_xxx）：12 個

### 2. 限制說明
- `/api/Services/service_list` 固定只回傳 **前 10 筆**，無法翻頁
- 但 `/api/ServicesInfo/pricing` 可取得 **全部 63 筆** 的 serviceId、名稱、價格、文件連結
- 各服務的 Swagger/OpenAPI 規格文件存在 **Google Drive**（documentUrl 欄位）

### 3. 技術文件
- 每個服務有獨立的 `documentUrl`（Google Drive 連結）
- 文件格式：Swagger/OpenAPI YAML/JSON
- 範例：`https://drive.google.com/open?id=1zTM_uih8qK1X3hTedbzISqNs_LcQ5Lsz5KZcPpDHJ8k`

## 四、爬蟲腳本規劃

```
腳本執行流程：
┌─────────────┐
│  1. 抓取    │ → /api/Portal（入口資訊）
│   入口資訊   │ → /api/SiteInfo/news（最新消息）
└──────┬──────┘ → /api/SiteInfo/qa（常見問題）
       │
       ▼
┌─────────────┐
│  2. 抓取    │ → /api/ServicesInfo/pricing（全部 63 筆）
│   服務價格   │ → /api/Services/service_list（前 10 筆含描述）
└──────┬──────┘ → /api/ServicesInfo/serviceUsage（全部 22 筆）
       │
       ▼
┌─────────────┐
│  3. 合併    │ → 將 pricing + service_list + usage 合併
│   資料輸出   │ → 產出每個服務的完整 JSON
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  4. 整理    │ → 依服務類別分資料夾（API / WFS / WMS）
│   分類儲存   │ → 每個服務獨立 JSON + 文件連結清單
└─────────────┘
```

## 五、重要新發現：靜態 HTML 說明文件

除了動態 API 之外，**每個服務都有獨立的靜態 HTML 說明文件**！

```
路徑格式：
/Service/service_Introduce/service_desc_{serviceId}.html

範例：
https://cop.moi.gov.tw/Service/service_Introduce/service_desc_24ED4437-DD2B-4FC1-A246-1AEF73681E0B.html
```

這些 HTML 文件包含 **完整的 API 規格**：
- 查詢介面名稱（如 QueryByLandNo）
- 輸入參數（必填/選填、資料型態、說明）
- 輸出欄位（欄位名稱、中文說明）
- 代碼對照表
- 單次查詢上限

**全部 63 個服務都有對應的靜態 HTML 文件！**
