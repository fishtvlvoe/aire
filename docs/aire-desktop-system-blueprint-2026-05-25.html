白話結論

AIRE 的客戶操作不應該看到 R02、COP、API、Helper、JSON 等底層名詞。客戶只需要先輸入地址，確認系統補出的地段、地號、建號，接著產出物調、補件、預覽與 PDF。工程與管理細節放在查詢紀錄與設定頁。

2. 物件分類與判斷規則

物件判斷來源系統可自動帶入現場仍需確認物調方向
大樓建物樓層與集合住宅條件樓層數、樓層別、建號、建物面積、主要用途電梯、車位、漏水、管理狀態建物版
華廈8 至 11 層、集合住宅、通常有電梯建號、樓層、用途、建物完成日期電梯、水塔、車位、公共設施建物版
公寓通常無電梯，樓層較低建號、樓層別、面積、用途無電梯、漏水、頂樓或增建、通行建物版
透天建物型態與門牌對應建號、土地地號、面積、用途車庫不一定有、騎樓、店住、漏水、通行建物 + 土地
別墅有車庫的透天型態建號、土地地號、建物資料車庫、庭院、社區管理、通行建物 + 土地
住宅建地都市計畫住宅區或可建築用地地段、地號、公告現值、使用分區臨路、套繪、建築線、通行土地版
農地農牧用地或非都市土地使用類別地段、地號、公告現值、使用地類別農路、水源、套繪、農舍可能性土地版
工業地工業區或丁種建築用地地段、地號、使用分區、公告現值污染、道路、廠登、水電容量土地版

分類原則

地政資料能確定的先自動帶入；謄本不會登載、但買方一定會問的資訊，保留在現場必問或補件欄位。車庫、電梯、水塔、漏水、壁癌、通行狀況不能只靠地政資料判斷。

授權 UX 原則

客戶只需要知道「帳號是否能用 AIRE」與「地政查詢是否已設定」。不要把 OAuth、API、token、COP endpoint 等名詞放在每日操作流程中。

桌面版完成標準是 macOS 與 Windows 都可以安裝、啟動、跑完整案件流程、保存 JSON/費用/log、產出 PDF。單純 Next build、Tauri build 或 mock E2E 綠燈都不算完成。

更新排程

先完成 Desktop fullflow 與 macOS/Windows 實機驗收，再做自動更新。自動更新不能早於桌面完整版，否則只是把半成品更快送到客戶電腦。

7. 斷點、紀錄與修正對策

斷點會發生什麼系統要留下什麼對策
地址候選不唯一可能對到多筆地號或建號候選 JSON、信心狀態、人工確認紀錄不進正式查詢，請使用者確認
地址查不到沒有候選地段/地號/建號lookup_failed log、輸入地址人工補填地段、地號、建號
COP 憑證錯誤正式查詢失敗credential_required 或 auth_error log系統設定提示重新設定客戶 COP
重複查詢同物件可能浪費費用cacheHit、sourceRunId、totalCostCents=0命中快取自動帶入，不打新 API
PDF 產出失敗文件不能交付PDF error log、使用的查詢 JSON id修 PDF，不重新扣地政查詢費
Windows/macOS 安裝失敗客戶不能使用 Appinstaller log、平台版本、簽章狀態release blocker，不標記完成
更新失敗版本無法升級update_failed log、目前版本、目標版本保留舊版可用，允許稍後重試

最終完成定義

客戶在 AIRE Desktop 輸入地址後，可以低噪地完成資料確認、正式查詢、物調補件、預覽與 PDF；管理者可在系統內看到 JSON、費用、cache 與錯誤 log；macOS 與 Windows 都有實機驗收；未來可用自動更新把修正送到客戶端。
