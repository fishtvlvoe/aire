# AIRE 核心業務邏輯

> 最後更新：2026-05-19  
> 這份文件是 Fish 親口說明的業務流程，未來讀這份文件，不要再問 Fish 同樣的問題。

---

## 兩份文件的差異

### 1. 不動產草稿書（Draft Dossier）

- **產出時機**：業務尚未與業主簽約前
- **內容來源**：地政 API 抓取的謄本資料、公開資訊、AI 產出的數據圖表與格局圖
- **資料狀態**：「暫定」—— 這些資料可能不完整或待確認
- **用途**：業務帶去現場，與業主核對並簽合約用的範本
- **系統對應**：`status = "draft"`，`disclosure_drafts` 表的 `payload_json`

### 2. 不動產說明書（Official Disclosure）

- **產出時機**：業務從現場回來、合約簽好後
- **內容來源**：草稿書內容（前面不變）+ 業務現場回補的資料
- **差別**：結構同草稿書，但最後一頁加入「客戶簽名頁」
- **前面欄位**：業務在現場與業主核對，手繪格局圖、拍照、記錄，回來後上傳至 AIRE 系統回補
- **系統對應**：`status = "completed"` 或觸發匯出 PDF 含簽名頁

## 完整流程圖

```
[業務建案]
    │
    ▼
[填入基本資訊]  ←── Step 1（地址、業主、物件類型）
    │
    ▼
[物件資料]      ←── Step 2（地號、建號等）
    │
    ▼
[揭露資料]      ←── Step 3（成屋/土地揭露表單，autosave 至 disclosure_drafts）
    │
    ▼
[實價登錄]      ←── Step 4（地政 API 資料，預留）
    │
    ▼
[PDF 預覽]      ←── Step 5（草稿書 PDF，可 inline edit 封面欄位）
    │
    ▼
【產出草稿書 PDF】── 業務帶去與業主簽約
    │
    │  (業主簽約後)
    ▼
[業務回補資料]  ──  補件入口（照片/格局圖/缺漏欄位）
    │
    ▼
【產出說明書 PDF】── 前面內容不變 + 最後加客戶簽名頁
```

## 補件邏輯

- 草稿書中有些欄位是空白的（現場才能確認）
- 業務回來後透過補件功能上傳：
  - 現場照片
  - 手繪格局圖（或拍照）
  - 物件外觀圖片
  - 缺漏的必填欄位值
- 補件完成後，所有欄位打勾 → 觸發說明書 PDF 產出

## 重要設計原則

1. **草稿書 ≠ 說明書**：兩者是同一份 PDF 模板的不同狀態，不是兩套系統
2. **前面不變**：說明書的前面內容與草稿書完全相同，只差最後的簽名頁
3. **補件不是 popup**：補件功能應嵌入在案件頁面（不是 dialog），讓業務隨時補填
4. **PDF 直接編輯**：業務填寫欄位的最佳 UX 是直接在 PDF HTML 頁面點擊打字，而非獨立表格
