## 唯一文件：不動產說明書

AIRE 只有一種文件，統一稱為「**不動產說明書**」。  
沒有「草稿書」與「說明書」之分——兩者是同一份文件的不同填寫狀態。

```
【不動產說明書】
├─ 前面 N 頁：物件資訊（初期部分空白，逐步填入）
└─ 最後一頁：客戶簽名欄（一開始就在文件裡）
```

---

## 完整作業流程

```
[1. 建案 & 產出說明書初稿]
       │
       │  系統自動填入（地政 API + AI）
       ▼
[說明書 PDF]──→ 業務帶去現場
       │
       │  現場：業務手寫確認所有資訊
       │        客戶核對無誤後簽名（最後一頁）
       ▼
[2. 回到店面，Key 入電腦]
       │
       │  業務對照現場紙本，逐欄 Key 入 AIRE
       │  確保內容與客戶簽名版本一致
       ▼
[3. 說明書完成]
       │
       │  所有欄位填齊 → 說明書轉為正式版
       ▼
[匯出最終 PDF]
```

## 補件邏輯

業務現場回來後，透過 AIRE 補件功能上傳：

| 補件類型 | 說明 |
|---------|------|
| 現場照片 | 物件外觀、室內狀況 |
| 格局圖 | 手繪或拍照，回傳 AIRE |
| 缺漏欄位 | 現場才能確認的數值（面積、屋齡、現況等）|

補件完成 → 所有必填欄位打勾 → 觸發最終 PDF 匯出。

## 設計原則（Fish 定義）

1. **一份文件**：沒有草稿/正式之分，就是同一份說明書漸進填入
2. **最後一頁簽名**：簽名欄從一開始就在文件裡，現場簽完帶回
3. **補件嵌入**：補件 UI 應嵌入在案件頁面，不是 popup dialog
4. **PDF 直接打字**：欄位編輯最佳 UX 是點擊 PDF 頁面直接輸入
5. **Key 入一致性**：回店後 Key 入的資料必須與客戶簽名版本完全一致
