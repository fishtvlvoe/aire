AIRE 門牌 / 地段地號 Discovery 判斷流程

目標是避免拿模糊地址直接打付費 COP。系統先用便民 / EasyMap R02 做零成本 discovery，只有取得可確認的 registry key 後，才進入正式地政 API、cache 與 PDF。

門牌路徑 地段地號路徑 正式 COP PDF 產出 人工補正

核心規則

  • 門牌有縣市、區、路街、巷弄與「號」，優先走門牌查詢。
  • 地段有縣市、區、地段、地號，走土地地號查詢，不走門牌 parser。
  • 禁止查不到、路名疑似錯、R02 500、多筆低信心時，不可自動打 COP。
  • 付費正式 COP 只接受 confirmed registry key，不接受 raw address。

Yes / No 判斷流程圖

每個 No 都要停住，顯示需要補填的資料或人工確認原因；不得把 No 當 partial success。

Start 輸入內容

使用者輸入門牌地址、地段地號，或不完整線索。

Q1 是否有完整門牌？

縣市 + 區 + 路/街 + 巷/弄 + 號。

Yes → 門牌路徑
No → Q2
A 門牌解析

拆成 cityCode、townName、roadName、lane、alley、number。

Q1-1 R02 門牌是否精準對回？

回傳門牌必須與輸入號碼一致；不能選相近號碼。

Yes → 座標反查
No → 人工確認
A1 座標反查地籍

門牌 detail → x/y → Land_json_getMapImageLayersByCoord。

A2 土地明細與建號

LandDesc_ajax_detail 取得地段、地號、建號清單。

Start 輸入內容

同一輸入若不是完整門牌，進入地段地號判斷。

Q2 是否有地段 + 地號？

例：台南市永康區勝利段1043-0002。

Yes → 地段路徑
No → 補資料
B 地段地號解析

拆縣市、行政區、地段名稱、地號主號/副號。

Q2-1 地段是否唯一？

查 City_json_getSectionList / SectionTownCode。

Yes → 驗證地號
No → 人工選地段
B1 地號是否存在？

Land_json_locate 檢查 office + sectNo + landNo。

B2 土地明細與建號

LandDesc_ajax_detail 取得土地資料，若有建物列出建號候選。

Q3 是否有可確認候選？

門牌或地段路徑只要低信心，就不得前進。

Yes → 候選確認
No → registry_pending
Q4 使用者是否確認？

單筆可預填，多筆需選擇；人工補正也要確認。

Yes → confirmed key
No → 不打 COP
COP 正式地政 API

依建物或土地類型選 minimal API set，先估價再查。

DB 本機保存與 cache

保存 raw JSON、parsed JSON、費用、cacheHit、sourceRunId。

PDF 物調 / 預覽 / PDF

只讀本機已保存資料；PDF 不重新打付費 API。

Stop 人工補正路徑

缺縣市、區、地段、地號、門牌、建號或候選低信心時，建立 pending 或要求補件。

每條路徑要填什麼、會得到什麼

路徑 Yes 條件 No 時怎麼處理 缺漏要補哪些資料 成功輸出
門牌號碼 輸入含縣市、行政區、路街、巷弄、號，且 R02 回傳門牌能精準對回。 路名錯字、號碼不同、R02 500、回傳空結果時，不打 COP，進人工確認。 正確門牌、縣市、行政區、路街名、巷弄號；必要時由業務改正路名。 地段、地號、建號候選；有建號則先視為建物候選。
地段地號 輸入含縣市、行政區、地段名稱、地號，且地段可唯一對應 sectionCode + office。 缺縣市/區、地段多筆、地號不存在，顯示 manual_required。 縣市、行政區、地段名稱、地號主號/副號；地段多筆時需人工選地段。 土地候選；若 LandDesc 有建號，附帶建物候選清單。
候選確認 候選只有一筆且高信心可預填；多筆時使用者選一筆。 使用者未確認前，禁止正式 COP。 地段、地號、建號可空但要明確標示土地或建物；多筆候選要選擇目標。 confirmed registry key，成為正式查詢唯一入口。
Pending 案件 業務仍要先建立案件，但地政鍵不足。 正式 COP、trusted PDF、正式地政欄位都被阻擋。 缺什麼補什麼：地段、地號、建號、正確門牌、權狀/謄本、屋主提供資料。 registry_pending 案件與補件清單，業務流程不中斷。

資料欄位與物件調查表差異

成屋 / 房子物調表

R02 / COP 可先帶入

  • 門牌地址、地段、地號、建號
  • 建物面積、主建物/附屬建物面積
  • 總樓層、本層樓層、用途、構造
  • 建築完成日期、屋齡
  • 所有權、他項權利、共同擔保資訊

仍需現場或人工補件

  • 委託總價、現況、租金、管理方式、管理費
  • 車位方式、車位號碼、電梯數、公設比
  • 社區名稱、建設公司、學校、公園、市場、商圈
  • 漏水、裝潢、違建、優缺點、照片
  • 圖資：地籍圖、空拍圖、格局圖、地標圖
土地物調表

R02 / COP 可先帶入

  • 縣市、行政區、地段、地號
  • 土地面積、使用分區、使用地類別
  • 公告土地現值、公告地價
  • 所有權、他項權利、權利範圍
  • 地上建物建號清單，如果該地號下有建物

土地專屬人工調查

  • 占用、出租、地上權、道路用地、法定空地
  • 既成道路、公共設施保留地、山坡地、原住民保留地
  • 水源保護區、自然保護區、國家公園、行水區
  • 嫌惡設施、未登記建物、地上物、墳墓
  • 土壤液化、斷層、高壓電塔、淹水、土石流、污染

API 資訊如何對應到 PDF

1

輸入解析

判斷是門牌或地段地號。

  • inputKind
  • normalizedInput
  • 缺漏欄位
2

R02 Discovery

零成本查候選，不當正式資料。

  • sectionName
  • landNo
  • buildingNo candidates
3

人工確認

生成 confirmed registry key。

  • confirmed section
  • confirmed landNo
  • confirmed buildingNo
4

正式 COP

依土地或建物選 API set。

  • 土地標示/所有權
  • 建物標示/所有權
  • 分區、地價、他項權利
5

本機 DB / Cache

PDF 與預覽只讀已保存資料。

  • raw JSON
  • parsed JSON
  • cost / cacheHit / sourceRunId
6

PDF 章節

依物件類型輸出不同內容。

  • 封面與物件基本資料
  • 土地/建物標示
  • 權利與限制
  • 物調表與圖資
建物分類

正式 COP 後細分

  • 大樓華廈：總樓層高、有電梯或集合住宅特徵
  • 公寓：低樓層集合住宅，通常無電梯
  • 透天別墅：整棟、樓層連續、非集合住宅
  • 套房：面積小、用途/格局符合套房
  • 店面、廠房、農舍：依用途與主建物資訊判斷
土地分類

正式 COP 後細分

  • 農地：農業區、農牧用地、特定農業區等
  • 商業用地：商業區或商業使用分區
  • 工業地：工業區或工業使用分區
  • 建地/住宅地：住宅區、乙種住宅用地等
  • 其他土地：無法安全歸類時保守分類
停損規則

避免浪費 COP 費用

  • 沒有 confirmed registry key，不打 COP
  • R02 查不到，不打 COP
  • 路名疑似錯字，不自動修正成成功
  • 多筆候選未選定，不打 COP
  • PDF 產生時不得重新打付費 API
