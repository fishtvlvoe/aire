AIRE 本機 Web / Desktop 地政流程對照圖

這頁是用來核對我們對流程的共同理解：先用 EasyMap R02 找地段、地號、建號，再由使用者確認，最後才用客戶自己的 COP 憑證查正式資料。

目前要鎖定的核心認知

地址不能直接被當成 COP 正式查詢條件；R02 是候選 discovery，COP 是確認後的正式付費資料來源。

主流程

1

輸入地址

使用者在新增案件輸入門牌地址。這只是 discovery input，不是正式查詢 key。

2

EasyMap R02 查候選

本機 Web 透過 local proxy，Desktop 透過 Tauri/Rust，去 R02 找地段、地號、建號。

3

人工確認地政鍵

R02 回來的是候選資料。使用者必須確認正確的地段、地號、建號。

4

按分類查 COP

系統依物件分類選最小必要 API 組合，用客戶自己的 COP 憑證查正式資料。

5

保存正式 JSON

保存 raw JSON、parsed JSON、費用、cache hit、sourceRunId、錯誤紀錄。

6

帶入物調與 PDF

物調、HTML 預覽、PDF 只讀已保存 JSON，不重新打 COP。

資料來源責任分界

EasyMap R02

只負責從地址找到候選的地段、地號、建號。

候選資料 不視為正式謄本 可供人工確認

COP

只在地政鍵確認後執行正式查詢，且依分類選最小必要 API。

正式資料 客戶憑證 付費/計費

AIRE 本機資料庫

保存查詢結果與證據，讓後續流程不必重複打付費查詢。

raw JSON parsed JSON ledger

COP 最小 API 組合

案件型態 觸發條件 預設要查的 COP API 不該做的事
建物案件 R02 或人工確認後有建號。 building_registry, building_ownership, land_registry, land_value, mortgages, building_other_rights, zoning 不要只用地址打 COP；不要全部 API 無差別查。
土地案件 只有地段、地號，沒有建號。 land_registry, land_value, co_owners, mortgages, zoning 不要查建物 API；沒有建號時不要假造建號。

案件分類推導

R02 階段只能粗判斷

有建號先判定為建物類；只有地號先判定為土地類。R02 不足以直接判斷完整物件分類。

建物類 土地類 待確認

COP 回來後細分類

用用途、構造、樓層、總樓層、土地使用分區與土地類別推導細分類，並讓使用者可修改。

農地 透天別墅 公寓 大樓華廈 建地/住宅地 農舍 套房 店面 廠房 工業地 商業地 鄉村區建地 其他土地
系統可以自動帶入分類，但 UI 要標示為系統判斷並提供人工覆核；不能只剩「成屋 / 土地」兩類。

禁止事項

  • 不能把 mock 0001/0001/0001 當作自動補齊成功。
  • 不能用地址直接觸發正式 COP 付費查詢。
  • 不能在未確認地段、地號、建號前打 COP。
  • 不能在 HTML 預覽或 PDF 生成時重新打 COP。
  • 不能把客戶 COP 憑證放在 browser bundle、localStorage 或可見 payload。

核對清單

  • 入口/cases/new 是唯一地址查詢入口。
  • Discovery先 R02 找候選地段、地號、建號。
  • 確認使用者確認後才進正式 COP 查詢。
  • 分類系統自動帶入完整分類，且可人工修改。
  • API依分類查最小必要 COP API 組合。
  • 保存正式 JSON 與 ledger 寫入本機資料庫。
  • 重查同物件先走 cache，不重複扣費。
  • 輸出物調、預覽、PDF 只讀保存資料。
